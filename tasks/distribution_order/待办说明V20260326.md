

## 1. 后端调用说明

### 1.1 待办任务入队（生产者）
*   **模块路径**: `apps/common/service/todo_queue_sender.py`
*   **职责**: 将待办任务数据写入 Redis 队列。
*   **调用方式**: 业务逻辑中直接调用 `todo_queue_sender` 模块。
*   **返回值**: 
    *   `True`: 任务入队成功。
    *   `False`: 任务入队失败（需检查日志或返回错误信息）。
*   **参考**: 请参照 `todo_queue_sender_test` 接口的调用方式。

### 1.2 待办任务处理（消费者）
*   **模块路径**: `apps/common/service/todo_woker.py`
*   **职责**: 常驻后台的 Redis 阻塞消费者，实时监听队列并执行数据库更新/插入操作。
*   **注意**: 业务代码**无需**直接调用此文件，仅需通过发送端发送任务即可。

### 1.3 启动/管理命令
*   **线上环境 (预发服务器)**:
    ```bash
    cd /home/www/project/internalapp_serve && sh manage_todo_worker.sh [start|restart|reload|stop|status]
    ```
*   **测试环境**:
    ```bash
    cd /home/dev/www/internalapp/internalapp_serve && sh manage_todo_worker.sh [start|restart|reload|stop|status]
    ```
*   **✅ 建议**: 部署或调试时，优先使用 `status` 确认运行状态；代码修改后使用 `reload` 或 `restart` 生效。

## 2. 待办数据体说明

### 2.1 数据结构概览
```json
{
     "title": "种草计划待办",
     "todo_keywords": "plan_submit",
     "redirect_params": { "plan_id": "RC2512118268TT" },
     "related_id": "RC2512118268TT",
     "menu_id": 318,
     "todo_level": "P0",
     "add_param": { ... },      // 新增待办参数 (可选)
     "update_param": { ... },   // 更新待办参数 (可选)
     "note": "",
     "queue_name": "todo_queue"
}
```

### 2.2 必填字段校验
| 字段                          | 类型 | 是否必填     | 说明                                                         |
| :---------------------------- | :--- | :----------- | :----------------------------------------------------------- |
| `related_id`                  | str  | ✅            | 业务关联 ID（如订单ID、工单ID），用于唯一索引。              |
| `todo_keywords`               | str  | ✅            | 待办类型关键词（由后端自定义，与 related_id 组成唯一索引防止重复）。 |
| `menu_id`                     | int  | ✅            | 菜单 ID，用于前端跳转定位。                                  |
| `todo_level`                  | str  | ✅            | 优先级，枚举值：`'P0'`, `'P1'`, `'P2'`。                     |
| `add_param` 或 `update_param` | dict | ✅ (至少其一) | **二选一或共存**：控制是新增任务、更新任务还是流转任务。     |

> 📌 **唯一索引规则**: 数据库层面由 `menu_id` + `todo_keywords` + `related_id` 组成唯一索引。

## 3. 参数详解

### 3.1 `add_param` (新增待办)
当存在 `add_param` 时，表示创建一个新的待办步骤（流程起点或新节点）。

**核心字段**:

```json
{
    "todo_step_name": "审批环节",       // 步骤显示名称
    "todo_user_id": [154],             // 接收人用户ID列表 (必须是非空 list)
    "todo_step": "obsess_plan",        // 步骤英文标识 (唯一键)
    "note": "",                         // 备注 (可选)
    "level": "P1"                     // 【可选】细维度等级。若提供，level覆盖外层 todo_level。
}
```

### 3.2 `update_param` (更新/关闭待办)
当存在 `update_param` 时，表示对现有待办进行状态变更、等级调整或全量关闭。

**核心字段**:
```json
{
    "todo_step": "obsess_plan",        // 【必填】步骤英文标识 (COMPLETE_ALL 模式下可忽略)
    "todo_step_name": "...",           // 【可选】步骤名称 (仅用于日志或辅助显示)
    "todo_user_id": [154],             // 【可选】指定用户。若不传，默认操作该步骤下所有用户。
    "level": "P1",                     // 【可选】细维度等级。若提供，level覆盖外层 todo_level。
    "action": "COMPLETE_ITEM"             // 【可选】操作类型，默认 "COMPLETE_ITEM"，如果想执行默认更新，action字段可以不传
}
```

**`action` 操作类型详解**:

| Action 类型               | 说明           | 必填字段要求                            | 行为逻辑                                                     |
| :------------------------ | :------------- | :-------------------------------------- | :----------------------------------------------------------- |
| **`COMPLETE_ITEM`**(默认) | **关闭指定项** | `todo_step` (必填)`todo_user_id` (可选) | 1. 若传 `todo_user_id`: 仅关闭该步骤下指定用户的任务。2. 若未传 `todo_user_id`: 关闭该步骤下**所有**进行中的任务。 |
| **`COMPLETE_ALL`**        | **全量关闭**   | 无 (忽略 `todo_step`)                   | 忽略 `todo_step` 和 `user_id`，直接将该 `related_id` 下**所有**状态为“进行中”的明细全部标记为完成。适用于流程整体结束。 |
| **`UPDATE_LEVEL`**        | **更新等级**   | `todo_step` (必填)`level` (必填)        | 仅更新指定步骤的 `todo_level` 字段，**不改变**任务状态（保持进行中）。用于动态调整优先级。 |

> ⚠️ **校验规则**:
> 1. `todo_user_id` 若提供，必须是**非空列表**。
> 2. `UPDATE_LEVEL` 模式下，必须同时提供 `todo_step` 和 `level`。
> 3. `COMPLETE_ALL` 模式下，`todo_step` 字段即使传递也会被忽略。

## 4. 场景示例

### 场景 1: 新增待办 (流程起点)
*仅包含 `add_param`，表示创建新任务。*

```json
{
  "title": "种草计划待办",
  "todo_keywords": "plan_submit",
  "related_id": "RC2512118268TT",
  "menu_id": 318,
  "todo_level": "P0",
  "add_param": {
      "todo_step_name": "种草计划提交审核",
      "todo_user_id": [154],
      "todo_step": "obsess_plan",
      "note": "请按时提交"
  }
}
```

### 场景 2: 关闭指定步骤 (默认模式)
*仅包含 `update_param`，默认为 `COMPLETE_ITEM`。关闭 `obsess_plan` 步骤下用户 154 的任务。*

```json
{
  "title": "种草计划待办",
  "todo_keywords": "plan_submit",
  "related_id": "RC2512118268TT",
  "menu_id": 318,
  "todo_level": "P0",
  "update_param": {
      "todo_step": "obsess_plan",
      "todo_user_id": [154]
  }
}
```
*若不传 `todo_user_id`，则关闭该步骤下所有人：*
```json
"update_param": { "todo_step": "obsess_plan" }
```

### 场景 3: 流程流转 (先关闭旧任务，再新增新任务)
*同时包含 `update_param` 和 `add_param`。系统会先执行更新（关闭），再执行新增。*
```json
{
  "title": "种草计划待办",
  "todo_keywords": "plan_submit",
  "related_id": "RC2512118268TT",
  "menu_id": 318,
  "todo_level": "P1",
  "update_param": {
      "todo_step": "obsess_plan",
      "todo_user_id": [154] 
  },
  "add_param": {
      "todo_step_name": "经理审核",
      "todo_user_id": [201],
      "todo_step": "manager_audit",
      "note": "流转至经理"
  }
}
```

### 场景 4: 全量关闭 (一键结单)
*使用 `action: COMPLETE_ALL`。忽略具体步骤，关闭该单据下所有未完成事项。*

```json
{
  "title": "种草计划待办",
  "todo_keywords": "plan_submit",
  "related_id": "RC2512118268TT",
  "menu_id": 318,
  "todo_level": "P0",
  "update_param": {
      "action": "COMPLETE_ALL"
      // 此处不需要 todo_step，系统将关闭所有相关待办
  }
}
```

### 场景 5: 动态调整等级
*使用 `action: UPDATE_LEVEL`。仅修改某步骤的优先级，不完成任务。*
```json
{
  "title": "种草计划待办",
  "todo_keywords": "plan_submit",
  "related_id": "RC2512118268TT",
  "menu_id": 318,
  "todo_level": "P0",
  "update_param": {
      "action": "UPDATE_LEVEL",
      "todo_step": "obsess_plan",
      "level": "P1" 
  }
}
```
